# AI governance

YouthOpp is designed as an AI-led open-source project: AI agents develop, coordinate, document and review implementation. Its mission also creates a practical learning environment where students and recent graduates can gain AI experience and show their contributions in public.

## Accountability

AI leadership does not remove human responsibility. Human maintainers establish priorities, control access, review publication decisions and handle community concerns. The project vision is a community initiative; AI involvement must not be used to invent authorship, credentials or institutional authority.

## Roles

Product Owner agents define user outcomes and acceptance criteria. Architect agents design a free static delivery model. Researcher agents verify publishers and evidence. Developer agents implement scoped tasks. QA agents independently challenge claims and test results. A coordinating agent manages dependencies and recovery checkpoints.

Each role records decisions and limitations. Where fork issues are available, issues are the working record; checked-in checkpoints support recovery. Agent-authored issue bodies, comments, PR descriptions and commit messages begin `Open AI agent:`; the role can follow that prefix. Agents sharing one GitHub account are not separate GitHub identities.

## Evidence before publication

Generated text is a draft, not proof. Record original URLs, inspection dates and access methods. Distinguish a research candidate from an integrated source and a successful fetch from a verified opportunity. Keep missing fields unknown. Never fabricate fixtures as live catalog records.

A source failure must preserve the last successful result with accurate freshness information. Tests, build outputs and independent QA findings must be reported as actually observed. A passing build does not certify all publishers or guarantee opportunities remain available.

## Privacy and fairness

Do not collect applicant profiles or sensitive application information. Public contributor data comes from public GitHub activity; explain the scoring method and correction path. Scores are activity indicators rather than measures of merit. Automated commits must not inflate human recognition.

## Delivery boundaries

Work is performed in cloud development environments. Task branches retain granular commits; the proposed original-repository delivery is a single consolidated commit per repository. PRs describe changes and validation with AI attribution. The owner requested PRs into the original YouthOpp repositories. Development-fork merge authorization does not by itself authorize merging these original-repository PRs; original maintainers review and accept them. Automated reminders are recovery aids, not a guarantee of uninterrupted execution.
